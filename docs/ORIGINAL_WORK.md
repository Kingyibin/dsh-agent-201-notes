# 原创边界（逐项署名）

用户要求的口径是「**只推纯原创，不要脱胎于别人项目的东西**」。按这个口径，
本次推送的三个仓库只收录 A 类；B 类只做文字说明，一行代码都不带。

## A 类：从零写的独立模块（本次推送）

| 模块 | 独立仓库 | 为什么算原创 |
|---|---|---|
| 云地记忆同步 | `dsh-cloud-memory-sync` | 定时/补跑/锁/账本/digest/换窝全部自写，不依赖任何上游项目代码 |
| 自托管工具箱 | `dsh-agent-selfhost-kit` | 部署脚本、systemd unit、看门狗均为自写；调用的是通用工具而非派生项目 |
| 能力位地图与工程实录 | `dsh-agent-201-notes` | 全部为原创写作，数字带核对时间戳 |
| 记忆压缩插件 | `dsh-memory-compaction`（已开源） | 自写摘要实现，替换运行时自带的一次模型调用 |
| 语音房插件 | `dsh-oopz-voice`（已开源） | 自写 ASR/TTS/推流链路 |

## B 类：上游派生或第三方（**不推代码**）

| 组件 | 来源 | 说明 |
|---|---|---|
| QQ 桥接基线 | `Derpyu520/qq-bridge` MIT | 本地版本是它的派生，README 与版本史均为上游原文；整包推送会造成归属误认 |
| 唤醒 / 权限 / preset / 账本等增量 | 写在上述派生仓库里 | 逻辑是自研，但**附属于上游代码树**，按本次口径不单独拆出 |
| DSH 运行时 | DeepSeek | 第三方运行时 |
| SnowLuma / NapCat / Tailscale | 各自项目 | 通用工具，仅被调用 |
| 长期记忆 / 心情 / 主动搭话 / B 站 / 子代理等插件 | 第三方作者 | 仅配置与集成 |

## C 类：运行时数据与用户内容（永不推送）

真实配置、会话日志、token 账本明细、群号、账号、票据、私聊原文、人设正文、
本地绝对路径。发布版一律用 `${...}` 占位，并在生成后做全量泄露扫描。

## 为什么要写这一页

「能力位」容易被读成「这些都是我写的」。实际上一个能跑的系统必然站在别人的运行时上。
把边界写死，既是不冒领，也让复现的人知道该去哪里拿真正的依赖。
